# MAP 地图块 + 图块集 + 调色板 + 渲染

> 解析/渲染器：`新建游戏项目/tools/map_render.py`
> 证据：`_rea_runtime/out/assets/assets_validate.json` 的 `checks.map` / `checks.pat`
> 结构语义参考 sdlpal `map.h` / `map.c` [inference]，尺寸、索引范围、渲染结果均用实际字节验证。

## 1. 容器与块尺寸 [observation]

`Map.mkf`：1614602 B，sha256 `62739644…bacd575`，**226 块**，头部 908 B；
0 号块为空（无地图 0），另有 2 个空块；其余 **223 块全部是 YJ2 压缩块**，
且每块解压后**恒为 65536 字节**（223/223 校验通过）。

```
65536 B = 64(x) * 128(y) * 2(h) * 4(DWORD)
```

**重要修正**：地图块内**不存储宽高**。地图逻辑网格固定为 64 列 × 128 行 × 2 个子层
（h=0/1），全图坐标范围是确定的 `64*32+16 = 2064` × `128*16+8 = 2056` 像素。
（sdlpal `PALMAP.Tiles[128][64][2]` 与此一致。）地图内容之外的网格用 0 填充。
因此 Godot 侧不需要"宽高字段"，只需要固定网格 + 视口滚动。

## 2. 图块 DWORD 位域（每格 2 个 DWORD：h=0 / h=1）

| 位 | 掩码 | 含义 |
|---|---|---|
| 0..7 | `d & 0xFF` | 底层图块号低 8 位 |
| 8..11 | `(d >> 8) & 0xF` | 图块高度/遮挡值（用于精灵与顶层的遮挡排序） |
| 12 | `d & 0x1000` | 未使用（实测恒 0） |
| 13 | `d & 0x2000` | **阻挡位**（1 = 不可通行） |
| 16..23 | `(d >> 16) & 0xFF` | 顶层图块号低 8 位 |
| 24..27 | `(d >> 24) & 0xF` | 顶层高度/遮挡值 |

索引公式（sdlpal `PAL_MapGetTileBitmap`，已用"索引 < GOP 帧数"逐图验证）：
```
底层图块号 = (d & 0xFF) | ((d >> 4) & 0x100)          # 9 bit, 0..511
顶层图块号 = (((d >> 16) & 0xFF) | ((d >> 20) & 0x100)) - 1   # 0 => 无顶层
含透明：底层为 0 时绘制 GOP 帧 0；顶层为 0 时跳过。
```
实测样例（map 12）：
```
d=0x0000005d -> 底层 93, 高度0, 阻挡0, 顶层 -1(空)
d=0x1027001c -> 底层 28, 高度0, 阻挡0, 顶层 294
```
map 12 共 2192 个非零 DWORD、692 个阻挡格；map 20（场景1，床）只有 15 个非零格，
内容包围盒为 x 14..17、y 23..26。

## 3. 图块位图来自 GOP.MKF（原样块）

`Gop.mkf` 226 块（3 个空块），**全部原样存储，不压缩**，块号与 Map 块号一一对应。
每块 = PAL sprite（帧表，见 MKF-FORMAT.md §3.3）+ BITMAPRLE 帧：
- 地图 1 的 GOP 块：`uint16 n=453` → **452 帧，全部 32×15**（菱形/斜视角图块）
- 全部 223 个有效地图块的 GOP 帧尺寸集合 = `{(32,15)}` ✔
- 每帧 = `w=32, h=15` + RLE 流；实测 map1 索引最大 450 < 452 帧 ✔；
  全体地图逐块校验"最大图块号 < 该地图 GOP 帧数" = **0 违例**
- 图块位图**没有** `02 00 00 00` 前缀（GOP 帧直接以 w,h 开头）

## 4. 32×16 图块的拼接/绘制规则

sdlpal `PAL_MapBlitToSurface` + `PAL_XYH_TO_POS`：
- 地图格 `(x, y, h)` 的图块（32×15 像素）绘制到全图像素位置
  **`px = x*32 + h*16`，`py = y*16 + h*8`**（h=1 的图块向右下错开半格，形成斜视拼贴）。
- 绘制分**两遍**：先整张底层（layer 0）再整张顶层（layer 1），
  否则顶层会被后续底层覆盖。
- 视口滚动：屏幕 320×200 = 视口在全图中的矩形；PAL 用
  `PAL_XYH_TO_POS(x,y,h) = (x*32+h*16, y*16+h*8-8)` 定位精灵，
  即图块基准比上面的公式整体上移 8 px；渲染全图时两种写法可互换（整体平移量固定）。
- 图块像素索引 0 = 透明（绘制时保留下层/背景）；全图空白处为黑。
- 遮挡：底层/顶层的 `(d>>8)&0xF` 高度值用于"精灵 y 排序"，静态渲染不需要。

## 5. 调色板（PAT.MKF）

`Pat.mkf` 8488 B，9 块，全部原样存储：

| 块 | 大小 | 说明 |
|---|---|---|
| 0 | 1536 | day(768) + night(768) 两套 |
| 1..4 | 768 | 仅 day |
| 5 | 1536 | day + night |
| 6..8 | 768 | 仅 day |

- 格式：每套 256 × RGB 三字节，**6-bit VGA 值（实测 max=63）**，转 8-bit：`c << 2`。
- 场景用哪套调色板由脚本 `set palette` 操作码决定，**不在地图块里**；
  游戏初始 `wNumPalette = 0` [inference]。本次渲染统一用块 0 的 day 调色板。
- 渲染器 `map_render.py` 支持 `--map <id>` 指定地图、内部 `pat_index` 切换调色板。

## 6. 渲染验证（已用 read_image 亲眼确认）

产物：

| 文件 | 场景 | 地图 | 尺寸 | 观察结论 |
|---|---|---|---|---|
| `_rea_runtime/out/assets/map_scene1.png` | 场景1 | 20 | 176×96 | 黑底上一张**床**（斜视角木床+被褥），是开场"李逍遥卧房"特写地图；内容仅 15 格 |
| `_rea_runtime/out/assets/map_scene2.png` | 场景2 | 12 | 1360×1184 | **6 间客栈客房/厅堂**：可见木地板、墙壁、门窗、床、桌、柜、屏风、盆栽，颜色正常、拼贴无缝 |
| `map_scene3.png` | 场景3 | 12 | 1360×1184 | 同上（场景2/3 共用地图 12） |
| `map_scene4.png` | 场景4 | 10 | 944×560 | 客栈大厅：石砖地、木桌、楼梯、柜台，斜视角透视正确 |

- `map_scene2.png` 中 6 个房间之间是黑色（该地图块中未放置图块的网格区 = 透明/空），
  说明"地图块 = 一个可含多个房间/区域的大画布，场景只决定出生点/事件对象范围"，
  而不是"一块地图一个房间"。
- 渲染方法：`for layer in (0,1): for y in 128: for h in (0,1): for x in 64:`，
  逐帧 RLE 解码后按 §4 位置写入 numpy 画布，最后 `palette[canvas]` 转 RGBA。
- 复跑：`python tools/map_render.py`（默认渲染场景 1..4，输出到 `_rea_runtime/out/assets/`）。
