# R124 白河村地面误封修复（tile id 0 合法地面）

## 现场
- 用户最新槽1（10/31 02:45，sha `85F1DDD…`）：scene50 绝对位置 **(1120,720)**，HUD「出村前往将军冢｜↓ 剩554格」。
- 周围逐格探测：大量地面格被 `_is_obstacle` 判不可走，但地图数据为
  `bottom tile = 0 / top=-1 / blocked=0 / content=0`，例如 (1104,696)、(1120,696)、(1152,720)、(1104,720) 等 → 走路“像有看不见的障碍”。

## 根因
- `PalMap.has_content` 旧规则：`idx_bottom > 0 or idx_top >= 0` 才算有地砖；
  **tile id 0 被当成空**（R99-BLACK-2 反黑区规则）。
- 实际 MAP.MKF 中 **tile id 0 是合法底图**：map46 的 tile0 位图是**草地/泥地**（有非透明像素，原版会绘制）。
  原版 `PAL_MapTileIsBlocked` 只看 blocked 位（0x2000），tile0 地面本来可走。
  移植把“content=0”当黑区封掉 → 村内成片 tile0 地面不可走，并让 HUD 绕路（N 偏大）。

## 修复（pal_map.gd，R124-GROUND-1）
- 加载地图时预计算每个 tile 位图是否含非透明像素（`_frame_opaque`，按数据/alpha，不看屏幕亮度）。
- `has_content` 改为：**bottom tile 位图确有非透明像素** 或 top overlay 存在 → 有地面内容；
  tile id 0 若位图是草地/石板/装饰地面 → 可走；仅**整块透明/无图块**才算黑区无内容。
- 不变：`blocked` 位（真实墙/障碍）仍不可走；开放水面（R120 WATER_TILE_IDS + 无桥 overlay）仍不可走；
  桥/桥头浅滩仍可走。

## 验证（headless，槽1 只读）
- 用户位置 (1120,720) 周边旧误封格现全部 `_is_obstacle=false`：如 (1104,696)/(1120,696)/(1152,720)/(1104,720)。
- 开放水面 (224,1448) 仍 `_is_obstacle=true / water=true`；桥 (640,1608) 仍可走。
- HUD 从 (1120,720)：目标 evt802，**N=538**（修复前 554，去掉了地面误封导致的绕路）；
  真实按键整段走到 (784,536) N=0 到 evt802 圈（全程 N 严格递减）。
- 从旧路线起点 (1600,720)：N 由 594 → **578**（地面打开后最短陆路变短）。
  ⚠ R123 的 7 段文件是按旧 594 路线生成，会与当前 HUD/最短路径不一致；需要时可重新按 578 路生成。
- 黑区安全性：只有 tile 位图完全透明/无内容仍算黑区不可走；`blocked` 位不变。
