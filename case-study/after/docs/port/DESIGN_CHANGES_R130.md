# R130 战斗消耗品掉落 + 数量 UI 对齐

## 1) 战斗胜利掉落消耗品（R130-LOOT-1）
- 每场胜利最多 1 件，**真实随机**；只掉真实消耗品（少量投掷物），结算文字显示「获得 XX ×1」，并真实进背包（`PALState.add_item`）。
- 档位按敌方总 HP/最高等级自动分档（不改队伍表）：
  - normal：总HP<700 且最高等级<10 → **30%**
  - elite：总HP>=700 或最高等级>=10 → **45%**
  - boss：总HP>=1800 或最高等级>=20 → **65%**
- 掉落表（真实物品 id，权重可调；代码常量 `BATTLE_LOOT_TABLE`，battle.gd 顶部）：
  - normal：止血草99(30) / 还神丹105(22) / 金创药101(14) / 鼠儿果104(10) / 蜂王蜜131(4) / 梅花镖153(6)
  - elite：止血草99(16) / 还神丹105(24) / 金创药101(16) / 鼠儿果104(12) / 蜂王蜜131(10) / 天仙玉露109(3) / 梅花镖153(6)
  - boss：还神丹105(22) / 蜂王蜜131(18) / 止血草99(14) / 金创药101(14) / 鼠儿果104(8) / 天仙玉露109(8) / 灵葫仙丹111(4) / 梅花镖153(4)
- 说明：A28 三敌合计2700HP → boss 档 65%；普通小怪 30%；不会必掉、不会连续刷屏（一场只判一次、最多1件）。

## 2) 数量 UI 对齐（R130-QTYUI-1）
- 问题：物品/出售列表原用“文字名 + 独立位图数字”分两处绘制（名 y=12/24号、数字 y=13~17、位图高度不同）→ 数量与名称基线错位、看起来“歪”。
- 修复：数量并入同一 Label、同一基线、同一字号：
  - 背包物品网格（menu_item.gd `_draw_grid`）：`名称  ×N`（size 21，clip 单元格）；
  - 使用对象页（menu_item.gd ItemUseTarget）：`名称  ×N`（同一 Label）；
  - 商店出售列表（shop.gd `_draw_sell`）：`名称  ×N`（size 21，clip）；
  - 战斗“物品/投掷”列表（battle.gd `_choose_item`）：`名称  ×N` + 效果同一条（`×` 与名称相邻）。
- 物品数量仍只在实际可用数量 >1 时显示（与原逻辑一致）。

## 3) 验收
- 打任意怪胜利：约 30% 概率结算多一行「获得 XX ×1」，背包对应物品 +1；A28 等 boss 约 65% 掉高级药（还神丹/蜂王蜜等）。
- 打开 物品/装备列表、商店出售列表、战斗物品/投掷菜单：数量 `×N` 与名称同一行、同一基线、不再错位/重叠。
