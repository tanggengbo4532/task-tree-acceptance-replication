# Lead 派单模板（向子 agent 分发任务）

> Lead 只做沟通、拆分与分发；每次派单必须让子 agent 拿到"可独立执行 + 可回执"的任务。

## 派给开发

- 任务类型：设计线路/细化节点 / 修复问题 / 设计层修复 / 任务树粒度复盘
- 当前节点与验收目标：
- 已知问题（台账编号 + 现象 + 证据路径）：
- 期望产出：任务树/代码 commit/最小复验步骤/风险
- 限制：不跑黑盒、不写记录归档；单实例窗口

## 派给测试

- 当前节点（编号/t_node/名称/主线）：
- 四要素：人（谁）/ 地点（在哪）/ 做到什么（事）/ 时间（t_node；t_exec 由测试侧记录）
- 验收标准（可判定）：
- 存档锚点：
- 经验库路径（必须开工前读）：
- 允许的操作（只键鼠、看画面；禁止读源码/数据/日志/存档内容）：
- 证据目录（文件名以 t_node 前缀，如 `r<t_node>_*`）：
- 停止条件（卡住 N 分钟即停）+ 报告模板路径
- 回执：**先自己判断节点是否完成**（结论 + 证据 + 未达成项 + t_node/t_exec）+ 问题清单 + 改进建议（现象/位置/截图/复现/期望vs实际）

## 节点推进（双确认，写死）

- 节点完成 = **测试自判完成 + 开发复核确认**；两者都确定完成，Lead 才派下一节点；
- 任一方"未完成"→ 继续本节点；双方不一致 → Lead 组织复核（必要时用户裁定），不得单方面宣布通过；
- 派给下一节点时，Lead 在派单里注明"上一节点已由测试+开发双确认"。

## 派给记录

- 已完成节点（编号/t_node/名称/主线）：
- 输入材料（各轮 recorder-log/bug-ledger/tester-report/截图/git log）：
- 固定六项（缺一不可）：①完成节点任务 ②初状态→末状态 ③解决的问题（可配图）④修改的代码 ⑤代码的理解 ⑥任务树更新（只主线）
- 配图要求：关键通过/阻塞各 ≥1 张，相对路径且文件存在
- 产出：`recorder-report.md` + 主线任务树；回执六项齐全性与引用图清单

## 回执与验收

- 子 agent 回来 → Lead 先核对：是否回答了派单里的每个问题？证据是否可复核？口径是否越权？
- 不完整 → 打回同一成员重做（不换成员）；合格 → 转下一环节或向用户汇报。
