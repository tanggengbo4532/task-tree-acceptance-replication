# Tester assignment

Follow the [Tester role prompt](../references/roles/tester.md). Use only normal UI input, observable state, and materials supplied for the black-box test.

- **Node** — <`t_node`, actor, location, and observable goal>
- **Starting state** — <Read-only anchor, build, and target instance>
- **Experience** — <`EXPERIENCE.md` path and applicable S/F/R IDs>
- **Evidence** — <Screenshots, input trace, evidence directory, and any required intermediate checkpoints>
- **Stop condition** — <Stall limit, visible blockage, or time limit>

## Return to the Lead

- **Self-verdict** — <Pass, fail, or blocked, with `t_exec` and attempt>
- **Evidence** — <Expected versus observed for each acceptance item, with evidence IDs>
- **Open items** — <Untested conditions, attempts already made, and reason for stopping>
- **Issues and suggestions** — <Reproduction steps and a concrete next step>
- **Progress** — <Team continuation point and any user action needed>
- **Experience updates** — <New or revised S/F/R entries>

Save team progress before reporting a blockage. The Developer reviews the evidence and the Lead confirms the verdict.
