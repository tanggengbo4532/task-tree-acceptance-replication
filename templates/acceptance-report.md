# 验收报告（人读版）· <项目 / 版本>

> **硬要求**：这份报告是给"人"看的，必须做到——
> 1. 写清**从哪个节点到哪里**（节点路径，如：标题→开场对白→客栈房间→回廊→一楼大厅→店门→街道）；
> 2. 写清**发现了什么 bug**（现象 + 根因 + 台账编号）；
> 3. 写清**最终做了怎样的修改**；
> 4. **代码变动用 `git diff` 格式贴出来**（hunk + `-` 初始行 / `+` 最终行，类似 git），只放"基线 → 验收"两段对比，**不要中间迭代过程**；末尾附 4 个文件的完整未删减 diff；
> 5. 每处代码改动都要有**中文解释**（为什么改、改完行为怎么变）；
> 6. 关键通过/阻塞各配 ≥1 张截图（相对路径 Markdown 图片）。
> 读者对象：用户/项目负责人；3 分钟能看懂"走到哪了、修了什么、还剩什么"。
