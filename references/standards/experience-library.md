# 标准 · 经验库（S/F/R 编号、复用与边界）

> 经验库是**测试侧资产**（`EXPERIENCE.md`），不是源码笔记：只记"怎么做 / 哪里容易踩坑 / 怎么验证"。
> 相关：`SKILL.md` §4、`templates/experience-log.md`、`references/roles/tester.md`。

## 1. 编号与格式

| 类型 | 格式 | 内容要求 |
|---|---|---|
| 成功经验 | **S\<序号\>｜一句话标题** | 方法/按键串/判定方式 + **适用条件** + 证据编号 |
| 踩坑经验 | **F\<序号\>｜一句话标题** | 会误判/无效的做法 + 正确做法 + 证据 |
| 重复失败 | **R\<序号\>｜同类第 N 次** | 引用前几次 F/S + 分析 + 具体改进建议 |

每条建议 2~6 行，例：

```text
- **S378｜长直路卡顿量化（holdprobe 800ms×2）**：开阔直段 hold 800ms、每 ~90ms 抓帧，
  统计变化帧/最长冻结；<100ms 且变化帧≥8/10 判达标。适用：可移动直段，被挡/折角段无效。
  证据：round76/r76d_12（9/9、8/9；冻结 0/83ms）。
```

## 2. 写回时机

- **每轮结束立即写回**（别等下一轮补）：新增 S/F、更新"验证状态表"（哪项通过/失败/未覆盖）；
- 同类失败第 2 次：写 R + 停手分析，给开发**可执行建议**（改提示/交互/碰撞/布局），不要硬试；
- 经验库不写实现细节/源码片段；涉及内部机制的判断交开发白盒。

## 3. 复用规则（先读后测）

1. 开工先读"成功经验"：**直接复用**（锚点跳转、按键串、判定口径、工具命令）；
2. 再读"踩坑经验"：**主动避开**已知误判（如"画面静止=卡死"、忽略遮挡/停走、长按语义跨场景不同）；
3. 读"验证状态表"：知道哪些项已过、哪些未覆盖，避免重复劳动。

## 4. 边界与误迁移（最容易出错）

经验**不是普适真理**，迁移前核对适用条件：

| 例子（真实项目） | 失效原因 | 教训 |
|---|---|---|
| 87 键固定回放（某起点成功一次） | 起点/朝向偏移、低帧率丢键 → 只 -6 步 | 固定回放依赖**精确起点**；跨起点不复用（`round75/tester-report.md`、`round75/EXPERIENCE.md`） |
| 救援法（ESC→ESC→静置 20s→单键） | 只在"滑行/骑乘平台区"有效；走廊无效 | 先确认卡死类型（平台 vs 走廊）再用（`round75/EXPERIENCE.md` S360） |
| 1 秒/步 tap 节奏 | 长路 1000+ 步耗时超时；低帧率丢键 | 长按/短按按场景与帧率调整（`round75/tester-report.md` §25） |
| hold 900≈12 步 | 窄走廊/方向翻转区会过冲 | 长按只适合直道（`round76/EXPERIENCE.md`） |
| 像素箭头检测（大字 HUD） | 抗锯齿把 CJK 切碎、括号/数字误判成箭头 | 仅辅助，验收以人工单键为准（`round76/EXPERIENCE.md` F-R76d-3） |

规则：经验写明**适用条件**（起点/视角/帧率/提示版本/输入工具）；条件变化时降级为"待验证"；误迁移案例单独记 F。

## 5. 与"同类问题第 2 次→设计层修复"的配合

- 测试经验可指出"这类问题第 N 次"（引用历史 F/S），帮助开发判断是否系统性问题；
- 开发做设计层修复后，测试在经验库更新"该卡点已用新机制解决"（避免后续继续按旧经验绕）；
- 验证状态表与 `bug-ledger` 台账对账，避免"经验说已修、台账未关"。

> 经验库是**测试侧**文件：开发不代写、记录不改写；recorder 归档时只引用其编号与结论。
