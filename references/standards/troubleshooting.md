# 标准 · 常见环境坑与排障（Windows 桌面优先，引擎无关原则）

> 症状 → 可能原因 → 处理；标注真实项目来源。相关：`README.md`、`scripts/windows/PlaytestKit.ps1`、`scripts/windows/Capture.ps1`、`references/testing/playbook.md`。

## 1. 窗口/焦点

| 症状 | 原因 | 处理 |
|---|---|---|
| 发键无效，但截图在动 | 窗口不在前台/焦点丢失 | 发键前 `focus`；或 PostMessage 直发 HWND（需扫描码/lParam）；检查是否有弹窗/输入法/通知抢焦点 |
| 按键"串"到别的窗口/实例 | 多实例、按标题匹配抓到编辑器 | **单实例纪律**：测前关残留窗口；按 `process_name + MainWindowHandle≠0` 找窗，标题只作辅助 |
| 窗口最小化/被遮挡截图黑 | 窗口未恢复/被盖 | `SW_RESTORE` 后再截；截屏时临时置顶（`capture.topmost_ms`，默认 400ms）后恢复 |
| 界面无响应但游戏没死 | 走位死角/被挡（画面不变≠卡死） | 打开菜单/ESC 验证是否"未冻结"；用移动探针/帧差判断；见 §4 |

## 2. DPI / 分辨率 / 多屏

- **DPI 缩放**导致截图偏移/按键坐标错：启动脚本先 `SetProcessDPIAware()`（`capture.dpi_aware:true`）；多屏时固定主屏/窗口位置后再测。
- 窗口尺寸变化：`shot` 前 `info` 记录窗口 rect；截图/裁剪区域随窗口尺寸更新（`capture.crop_hint`）。
- 全屏/无边框独占：优先窗口化模式测试；独占全屏可能无法 PrintWindow/置顶。

## 3. 截图空白/全黑/花屏

- **PrintWindow 在 Vulkan/D3D/部分引擎下全黑**：`capture.method:"auto"`=先 PrintWindow，空白回退 `CopyFromScreen`（屏幕拷贝）；仍黑用 GetWindowDC+BitBlt 交叉验证。
- 判断"真实黑屏"vs"截图伪影"：多方法交叉 + 看 UI 是否可见 + 系统事件；不能只用一种截图下结论。
- 截图是"上一帧/旧帧"：截图前等待渲染稳定（动画/过场结束）；必要时连续抓 2 帧对比。

## 4. 按键丢失 / 低帧率 / 长按语义

| 症状 | 原因 | 处理 |
|---|---|---|
| 60ms 轻按经常不走 | press/release 落在两帧之间；帧率低 | 应用侧加输入缓冲（见 engineering-patterns §5）；测试侧加大 `default_hold_ms`（如 80~150ms）与 `gap_ms`；用 `walkprobe` 量化吞键率 |
| 长按零位移 | 按住被当成"单键"或窗口丢焦点；场景限速/被挡 | 先单键试 1~2 步确认可动；长按只适合直道；低帧率下按 800ms 采样验证 |
| 长按一次走太多/过冲 | hold 语义连续移动 + 方向翻转区 | 窄走廊用"单键+读数"；批次盲走会过冲（`round76/EXPERIENCE.md` F-R76d-2） |
| 连发太快被吞 | 引擎每帧只处理一次输入 | 控制 `gap_ms`（≥2~3 帧）；用回合制按键而非瞬时连发 |

**低帧率排障顺序**：①是否单实例/前台 → ②是否窗口在渲染（帧率探针）→ ③是否每帧重活（BFS/IO/文本）→ ④是否 debug 日志/浮层 → ⑤是否被遮挡/停走（画面不变≠卡顿）。

## 5. 回放/自动化不保真

- **逐键回放不能作为验收手段**：headless 与实机帧率/焦点/时序不同，同一按键序列在实机可能只走几步（真实项目：1315 键回放在实机失效）。
- 自动化"移动反馈选方向"会被**场景门/传送/动画**误导（画面大变=以为走成功）→ 排除场景切换帧或干脆人工单键。
- 像素识别（箭头/文字/数字）受抗锯齿、遮挡、缩放影响 → 关键判定用固定文案/多帧投票/人工核对；识别器只作辅助。

## 6. 其他常见坑

- **脚本编码**：Windows PowerShell 下纯 ASCII 最稳（中文标题/路径匹配易因编码失效）；PowerShell 5.1 与 7 行为差异注意。
- **UAC/权限**：管理员启动的游戏/窗口，低权限脚本可能无法发键/截图 → 同权限运行。
- **输入法/快捷键**：测试时切英文输入法；避免快捷键被系统/其它软件截获。
- **后台任务收尾**：主动杀进程后，托管后台任务报 failed 属预期，不是错误。
- **性能监视**：截图/连拍本身有开销（PrintWindow 20~30ms/帧），测帧率时先确认测量工具不干扰；GPU 加速的截图可能异步。
