# 槽安全铁律（v3.3.3）

> 版本：**v3.3.3**｜状态：**安全铁律（写死）**｜适用：Lead / 开发 / 测试 / 记录 + **所有自动化执行器**
> 关联：`references/testing/human-ai-dual-progress.md`（进度一用户/进度二团队）、`references/testing/progress-first.md`、`references/standards/no-cheat.md`、`templates/anchor-ledger.md`
> 一句话：**任何情况不写用户槽；自动化只写团队槽；注入按键前必须确认 UI=游戏世界；保存/读档必须显式槽位+归属校验；误覆盖=P0 立即停手上报。**

## 0. 事故引子（真实案例，2026-10-29）

- **事故**：测试自动化在**存档菜单**状态下触发「无 HUD 引导 → 误判为战斗/对白恢复 → **盲按 SPACE×20**」；存档菜单的 SPACE 打开「储存进度」并**默认选中进度一**，确认后**覆盖用户进度一（槽1）**。
- **后果**：用户原档「场景40 次数13 08:18」→ 被覆盖为「场景45 次数33 09:16」；**无法精确恢复**；团队槽2 正常；槽3/4/5 未变。
- **结论**：这是**可避免的 P0 事故**——根因是自动化**输入前置状态门禁缺失** + **保存槽位/归属校验缺失**。本文件四条铁律即由此事故而来。

## 1. 铁律一：用户槽不可变（任何情况不写用户槽）

- **用户槽**（进度一/槽1 等用户自己的进度槽）**冻结只读**：测试、自动化、修复、排障、验证——**任何情况都不写**（不保存/不覆盖/不清空）；
- **自动化只允许写团队槽**（进度二/团队专用槽）；团队手动保存也**只写团队槽**；
- 团队从用户槽接续时：**只读载入 → 另存团队槽**（见双进度规则）；
- 违反=**P0 事故**（见铁律四）。

## 2. 铁律二：自动化输入前置状态门禁（UI=游戏世界才注入按键）

- 注入任何按键前，必须**截图/状态分类确认当前 UI=游戏世界**；
- **禁止盲按**的场景：**菜单（含系统/存档/读档菜单）、存档/读档列表、对话框、战斗界面、过场/剧情、加载画面、结算界面**；
- **状态不明 → 停止注入**（fail-safe），不得猜；
- **禁止"猜恢复"**：不得用「SPACE×N」「按任意键」等盲操作尝试退出未知界面；
- **战斗恢复必须截图判断**（战斗界面/回合/结算），确认是战斗才发战斗按键；对白/菜单/存档同理，一律先截图分类；
- 菜单/存档场景**不得复用**「战斗/对白恢复」逻辑（这次事故就是复用导致）。

## 3. 铁律三：保存/读档必须显式槽位 + 归属校验

- **保存前**：必须显式指定**槽位编号 + 归属**（用户/团队），并**校验**该槽位是否允许写；未知归属/用户槽 → **禁止保存**；
- **禁止依赖默认槽位**：存档菜单的默认光标/默认槽位（通常为进度一）**不得**作为保存目标；必须显式导航到团队槽并**二次确认槽位/归属**；
- **自动化保存命令**必须携带 `slot + owner(team)` 参数，执行器强制白名单（只允许团队槽）；
- **读档**：优先只读；记录槽位/次数/时间；用户槽只读载入；
- 保存/读档动作失败或状态异常 → **停止**，不重试盲操作。

## 4. 铁律四：误覆盖 = P0 事故（立即停手上报）

一旦发生/疑似发生槽覆盖：
1. **立即停手**：停止自动化、不继续按键、**不尝试覆盖恢复**（避免二次破坏）；
2. **保留证据**：日志（含注入键序列/时间）、截图、槽位状态、时间线；
3. **如实上报 Lead/用户**：包括「无法精确恢复」这类事实，不得隐瞒/虚构恢复；
4. 登记事故（bug-ledger/incident 文件），复盘根因，执行器加固（见 §6）；
5. 后续自动化**只写团队槽**、输入前置门禁必须生效；
6. **验收结论按事实处理**：用户验收 PASS 的章节结论不因存档事故改变，但需向用户如实说明用户槽状态。

## 6. 执行器要求（dev2 安全执行器，写死）

自动化执行器（keyseq/walker/自动战斗/自动恢复）必须：
1. **pre-input 状态分类**：每段按键前截图/状态判定 UI 类型；非「游戏世界」不注入；
2. **存档/菜单检测**：识别系统菜单、存档/读档列表、对话框、战斗、过场、加载；命中即停（不按默认逻辑）；
3. **团队槽白名单**：保存命令只允许团队槽（slot + owner=team）；用户槽写入直接拒绝；
4. **显式槽位**：禁止默认槽位；保存前导航到团队槽并二次确认；
5. **禁止盲恢复**：无状态证据不 SPACE×N；战斗恢复必须截图判断；
6. **fail-safe**：状态不明/异常立即停止并记录（不重试盲操作）；
7. **日志**：记录每次注入键、UI 状态、槽位/归属、截图路径（供事后审计）。

## 7. 检查清单（每次自动化/手动保存前）

- [ ] 当前 UI 是否确认为**游戏世界**？（截图/状态分类）
- [ ] 是否在**菜单/存档/对话框/战斗/过场**？（是→禁止盲按，先处理/停止）
- [ ] 保存目标是**团队槽**吗？槽位编号 + 归属是否显式校验？
- [ ] 是否动到**用户槽**？（绝对禁止）
- [ ] 读档是否**只读**？是否记录槽位/次数/时间？
- [ ] 状态不明时是否**停止**（而不是猜恢复）？
- [ ] 失败/异常是否**保留证据**并上报？

## 8. 与其他规则的关系

- **双进度**（`human-ai-dual-progress.md`）：进度一用户专用、进度二团队专用；本文件补充"写入安全铁律"；
- **进度优先**（`progress-first.md`）：bug 先存**团队进度二**再报（不得存用户槽）；
- **no-cheat**：保存进度=合法存档操作，但**不得写用户槽/伪造进度/盲操作**；
- **锚点台账**（`templates/anchor-ledger.md`）：固定锚点只读、用户槽只读、团队进度二可覆盖；
- **验收**：PASS 结论不因存档事故改变，但事故须如实上报/归档。

## 9. FAQ

**Q：自动化需要保存团队进度时怎么办？** 只写团队槽（进度二），显式槽位+归属校验；禁止默认槽/用户槽。
**Q：菜单/存档界面能不能按 SPACE 退出？** 不能盲按；先截图分类，按已知安全路径退出或停止等人工处理。
**Q：战斗失败怎么恢复？** 先截图确认战斗界面/结算，再按设计恢复流程；不得盲 SPACE×N。
**Q：误覆盖了用户槽怎么办？** 立即停手、保留证据、如实上报；不尝试覆盖恢复；按 P0 事故处理。
**Q：用户验收 PASS 的章节会因事故改判吗？** 不会——验收基于用户确认；事故单独归档并如实告知用户。
