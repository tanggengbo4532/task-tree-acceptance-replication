# 黑盒测试手册（引擎无关）

> 适用：任何可"真实输入 + 观察画面"的应用（桌面游戏/桌面软件/Web/CLI）。
> 本手册是**测试 Agent（黑盒）**的操作规范；与 `SKILL.md` 总框架、`references/roles/tester.md`、`references/standards/*` 配套使用。
> 纪律优先级：**真实证据 > 推进速度**；**如实记录 > 看起来通过**。

---

## 0. 一条铁律

**只相信"真实输入 + 真实画面"能复现的事实。**

- ❌ 不读源码/内存/存档二进制/调试日志内部；不看开发者注解来判断用户会遇到什么；
- ❌ 不用调试键、传送、自动胜、跳过剧情/战斗、改档/造档来"取证"（见 `references/standards/no-cheat.md`）；
- ❌ 不自宣"节点通过"或"整体通过"——节点结论需要 测试自判 → 开发复核 → Lead 宣布（`references/standards/evidence-and-acceptance.md`）；
- ✅ 只写 `roundNN/tester-report.md` + `roundNN/EXPERIENCE.md`（外加本轮的截图/日志/探针产物）；
- ✅ 一切结论附**证据编号**；无法取证的部分如实写"未覆盖/黑盒无法自证"。

## 1. 每轮固定节奏（建议 30~60 分钟/节点）

| 步骤 | 动作 | 产出 |
|---|---|---|
| 1 | 读 `EXPERIENCE.md`：S* 复用、F* 避开、R* 注意边界 | 本轮"复用/避坑清单"3~5 条 |
| 2 | 确认构建：`git log -1`（或版本号）、tracked 干净、**单实例**（残留窗口先关）、记窗口 pid | 一行环境回执 |
| 3 | 启动（正常参数，禁调试模式）；`err.log` 期望 **0B** | `rNN.err.log` |
| 4 | 读锚点（只读、不覆盖），核对与 `anchor-ledger` 一致（场景/坐标/关键状态/UI） | 锚点核对行 |
| 5 | 按引导/验收标准真实操作；**每段截图 + 记提示原文 + 记实际位移/结果** | `rNN_*.png`、进程日志 |
| 6 | 卡点/异常 → 立即停手（见 §5），整理问题清单+改进建议 | 回执 §问题 |
| 7 | 自判：结论 + 逐条验收对照 + 证据编号 + **未达成项** | `tester-report.md` 结论段 |
| 8 | 写回经验库（新 S/F；同类失败第 2 次记 R 并给建议） | `EXPERIENCE.md` |

**时间盒**：每 8 分钟检查一次"是否有净进展"（关键指标如剩余格 N 下降、目标文本推进、界面切换）。
无净进展 → **停手**，不要"再试 100 次"。

## 2. 环境纪律（写死）

1. **单实例**：同一时刻只允许一个被测窗口。测前枚举并关闭残留窗口；记录当前 pid；发现用户/他人窗口 → **立即停键、关自己的窗口让位**。
2. **前台/焦点**：发键前确保窗口在前台（`PlaytestKit.ps1 -Action focus`）；`-Action info` 应显示 `fgIsGame=true`；前台不是被测窗口时，结果不可信。
3. **截图抗伪**：优先 `Capture.ps1 -Action shot`（DPI 感知 + 临时置顶 + PrintWindow 空白自动回退屏幕拷贝）；出现"全黑/空白/颜色数异常"时换方法复核（多帧、实屏拷贝交叉）。
4. **锚点只读**：只载入、不覆盖、不新建同槽位；每轮报告写"读档 N 次（哪个槽）、是否存档（应为 0）"。
5. **日志重定向**：启动即 `stdout→run.log`、`stderr→err.log`；err.log 非 0B 需解释（警告/崩溃/取证）。
6. **不启动第二个实例做对照**：对照实验用同一实例分轮跑，避免按键/截图串窗口。

## 3. 输入方法（黑盒只允许的输入手段）

| 手段 | 何时用 | 要点 |
|---|---|---|
| `-Action keys -Value "ENTER"` / `"DOWN,DOWN"` | 菜单/对白/离散操作 | 默认 hold/gap 来自配置；低帧率下加大 `keys.gap_ms` |
| `-Action hold -Value "DOWN,800"` | 连续移动/长按类交互 | 长按语义各应用不同（可能"按住连走"或"单次触发"）；先小样本验证再批量 |
| `-Action diag -Value "LEFT,DOWN,800"` | 斜向/组合键（引擎支持时） | 非必须；不可用时用短序列近似 |
| `-Action shot -Value "step_01"` | 每个关键状态 | 命名见 §6 |
| `-Action hint -Value "step_01"` | 只截提示条/文字区域 | 依赖 `capture.crop_hint`；用于快速核对文案 |
| `-Action info` | 窗口/焦点/尺寸 | 每次跑偏先查 info |

**输入类问题判定**（引擎无关的"体验 bug"）：按键有输入但角色/界面无反应、方向与提示不符、轻按丢失、长按不生效、连按被合并。
→ 用 `tools/probes/walkprobe.py` / `holdprobe.py` 量化（见 `probes-and-metrics.md`），不要只写"感觉卡/走不动"。

**禁用的"输入"**：调试快捷键、控制台命令、直接写内存/存档、自动脚本替玩家打（除非 Lead 批准用于**辅助走位**，且结论仍需真实操作复现；辅助脚本不得作为验收证据本身）。

## 4. 画面测量方法（引擎无关）

### 4.1 三种问题分别怎么测

| 问题类型 | 测法 | 关键读数 |
|---|---|---|
| 是否"移动/推进" | 逐键连拍：每按一次截一帧，比较区域像素 | 每键变化=移动；连续无变化=被挡/吞键/卡住 |
| 是否"卡顿" | 长按期间定间隔连拍（如每 90ms），统计变化帧与最长无变化时长 | 冻结时长（ms）、变化帧数（n/10） |
| 提示是否"一致" | 同一帧内同时记录：顶栏/中央条/地面标记/浮层/边缘箭头 | 引导元素清单，同一信息出现 ≥2 处=重复 |

### 4.2 区域裁剪（读提示/数字）

- 全图截图存档；**另存**提示区域裁剪（`Capture.ps1 -Action region -Region "x,y,w,h"` 或 `tools/screen/crop_region.py`），便于快速核对文字/数字。
- 提示区域因分辨率/窗口尺寸而异：先 `-Action info` 拿 client 尺寸，再用一帧确定坐标并写入本轮报告（下次可复用）。
- 读数（如"剩余 N 格"）优先人工读裁剪图；无 OCR 工具时不强行自动化——**人工读数慢但可靠**。

### 4.3 判定"是否真实变化"的像素阈值

- 比较两张同尺寸帧的灰度差；阈值从保守开始（差异像素比例 <0.05% 视为未变化，具体以实现工具 `tools/probes/common.py` 为准）。
- 注意：**角色原地转身/动画**也会产生小差异 → 必须结合"位置/数字/场景"等语义判断，不能只看"有像素变化"。
- **画面静止 ≠ 卡死**：可能只是"被墙挡住/等待输入/停走"（见 §5 的 F 类经验）。

## 5. 卡点判定与停手（困难即停）

### 5.1 停手条件（任一满足即停）

1. 同一位置连续 **8 分钟**无净进展（N/目标/界面不变，反复方向翻转或无位移）；
2. 四方向试探后仍无可行方向（"四向矩阵"全堵）；
3. 提示与实际明显不符且无法绕过（按提示必撞墙/被传回上一场景/循环上下楼）；
4. 出现拒绝式崩溃/黑屏/进程退出（先保日志与退出取证，再停）；
5. 需要判断"这是 bug 还是设计"而黑盒证据不足 → 停手，问题清单交 Lead。

### 5.2 停手时必采证据（缺一不可）

- **现象**：画面/文案原文（截图）、无反应/错反应的具体表现；
- **位置**：场景/关卡、坐标或可辨认地标、顶栏地点原文；
- **复现步骤**：按键序列 + 时长/间隔（"按 15 次↓，60ms 按下、200ms 间隔"这种粒度）；
- **量化数据**：N 轨迹（如 150→112→77→79…）、四向矩阵、探针 JSON（walk/hold/fps）；
- **主线相关性**：是/否 + 判断依据（剧情推进/场景门/关键战斗/验收目标/锚点）；
- **已尝试**：尝试次数/时长，避免下一轮重复劳动；
- **改进建议**：改成什么、为什么、预期效果（可执行，不要只写"修一下"）。

### 5.3 上报模板（抄用）

```text
【节点】<编号/名称>   【构建】<hash>   【结论】未通过/阻塞
【现象】<...>（截图 rNN_xx）
【位置】<场景/坐标/顶栏原文>
【复现步骤】<按键序列 + hold/gap>
【期望 vs 实际】<按引导应发生 A，实际发生 B>
【量化】<N 轨迹 / 四向矩阵 / holdprobe 冻结 ms / walkprobe 吞键率>
【主线相关?】<是/否 + 依据>
【证据】<截图/日志/探针文件编号>
【已尝试】<时长/次数/变体>
【改进建议】<改成什么/为什么/预期>
```

## 6. 证据命名与归档（只增不覆盖）

```text
roundNN/
├─ tester-report.md          # 只写这个 + EXPERIENCE.md
├─ EXPERIENCE.md
├─ rNN_00_title.png          # 轮次前缀 + 序号 + 语义
├─ rNN_05_hint_stairs.png    # 关键状态帧（语义后缀：_before/_after/_blocked/_pass/_hint）
├─ rNN_hold_*/rNN_walk_*/    # 探针采样帧
├─ rNN_run.log               # 运行日志
└─ rNN.err.log               # 错误日志（期望 0B）
```

- **前缀唯一**：每轮/每子轮一个新前缀（`r76b_`、`r76c_`…），禁止覆盖上一轮；
- **关键帧带语义**：`_before/_after/_blocked/_pass`，便于复核时快速定位；
- **生成清单**：`python tools/evidence/manifest.py --dir .\roundNN --out roundNN/evidence-index.md`（路径/sha256/分组/张数，只增）；
- **报告只增**：`tester-report.md` 按轮追加章节（§A/§B/…），不改写历史结论。

## 7. 不同应用形态的适配（backend 视角）

| 形态 | 输入 | 画面 | 读数 |
|---|---|---|---|
| Windows 桌面/游戏 | `scripts/windows/PlaytestKit.ps1`（PostMessage，带 scan code） | `Capture.ps1`（PrintWindow→屏幕拷贝回退） | 提示条裁剪 + 人工读 |
| Web | Playwright/Selenium 真实键鼠（`page.keyboard`/`mouse`） | 浏览器截图（含 viewport 裁剪） | DOM 文本（若允许，等价于"界面提示"；**不得读源码/内部状态**） |
| CLI/服务 | 真实 stdin/终端输入 | 终端输出/日志（仅用户可见输出） | 输出文本 |

> 换引擎/平台 = 按 `scripts/backends/CONTRACT.md` 实现 backend 动作（launch/close/focus/info/keys/hold/diag/shot/hint/可选 read_text）；**结论口径不变**（真实输入 + 可见输出）。

## 8. 常见误判与规避（经验）

- **画面静止 = 卡死？** ❌ 也可能是被墙挡住/等待输入/停走/遮挡。→ 用 walkprobe 看"按键是否有变化"，用四向试探确认可走方向。
- **能走 ≠ 引导对**：N 递减但方向与黄点/顶栏不一致仍是引导 bug；反之 N 偶发回升可能是绕行/更近吸附，需结合目标文本判断。
- **长按语义各场景不同**：同一应用不同场景可能"按住连走"或"单次触发"；不能拿一个场景的经验直接套另一个（记为 F 类经验边界）。
- **回放/录制键序列不能当验收**：录制端的节奏/帧率语义与实机不一致时会整体失配（案例见 `case-studies.md` C）；验收必须真实按键 + 逐段核对。
- **自动化"按画面变化选方向"不可靠**：会被场景门/动画/遮挡误导，只可辅助、不可作为结论来源。
- **一次流畅一次冻结 = 间歇性**：卡顿类问题必须重复采样 ≥2 次，否则容易误判"已修好"。

## 9. 回执（交给 Lead）

```text
【节点】<编号/名称>   【构建】<hash>   【结论】通过/未通过/阻塞（测试自判，待开发复核+Lead 宣布）
【环境】正常启动/无调试参数；单实例 pid；读档 N 次（槽）；未存档；锚点未覆盖
【逐条验收】<验收点 → 证据编号 → 结果>
【量化】<吞键率/冻结 ms/变化帧/N 轨迹/引导重复处数>
【未达成项】<如实；停手原因>
【问题+建议】<按 §5.3 模板逐条>
【经验】<新增 S/F/R 编号>
【纪律】真实输入、无作弊、err.log 0B（或已解释）
```
