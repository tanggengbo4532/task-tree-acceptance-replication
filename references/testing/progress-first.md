# Resume from verified progress

1. On a blockage, stop the action and save at the team's valid Progress II when possible. Record the slot, build, current location and UI, completed nodes, open work, and time. Then report the issue with its evidence.
2. After a repair, resume from the recorded point or a compatible fixed anchor for the affected node.
3. Keep accepted nodes final. Record explicit user acceptance directly. Reopen a node only after a new defect report for that node or a change to its implementation.
4. Keep Progress I user-owned and read-only to the team. Give the user a reproducible way to review team results. Once accepted, update the team continuation point and record alignment.

The handoff includes both progress points, user-accepted nodes, results awaiting user review, and the next action. See [dual progress](human-ai-dual-progress.md) and [slot safety](../standards/slot-safety.md).
